## 0. 执行摘要

1. **写操作门控在最需要它的地方失守**：4 个真实远端写入入口（保存/解除 CI 关联、确认关联仓库、AI 推荐一键关联、批量创建至云效）是裸 `<Button>` + 原生 `disabled`，没有 `WriteOpButton`/`WriteOpGatedTrigger`/`aria-disabled`/Tooltip/Toast 任何一层。只读模式下唯一防线是 Rust 层的 `ensure_write`。
2. **「只读原因不可见」被系统性放大**：`ui/button.tsx` 把 `disabled` 映射成 react-aria 的 `isDisabled`，RAC 对原生 `<button>` 输出 `disabled` 属性并把 `tabIndex` 置 −1（已在 `react-aria` 源码 `useButton.mjs` 核对）。全仓 99 处 `disabled={…}` 调用点因此**既不可聚焦、也不触发 hover**，Tooltip 永不出现 —— 这正是设计审计 A4 当年要修的反模式，现在换了个入口复发。
3. **设计令牌纠正只做了一半**：`theme.css` 只覆写了 `.button` / `.toggle-button` 的圆角，**漏了 `.tabs__tab`（编译产物 `border-radius:1.5rem` = 24px 胶囊）和 `.chip`（`border-radius:1rem` = 16px）**。DESIGN §2.2 要求内联小徽标 4px、拒绝胶囊，全站 Tabs 与 20+ 处 Chip 因此违规。
4. **浮层与键盘的层级契约靠各组件各自为政**：`Esc` 手写在 6 个文件里，`IterationView` 的捕获层没有 `hasSelected` 分支 → 多选非空时 `Esc` 直接关抽屉（越级）。抽屉套抽屉、Drawer 上再弹 AlertDialog 共 4 处。
5. **无障碍短板集中在表单与命名**：`<label>` 未关联输入 15+ 处、`FieldError` 在无 field 上下文时**永远返回 null**（已核对 RAC 源码）、12 个富文本工具栏按钮与 8 个 icon-only 按钮只有 `title` 没有 `aria-label`（`title` 只给鼠标用户）。
6. **壳层缺基础设施**：无 skip-link、侧栏无 `nav`/`aside` landmark（`ui/sidebar.tsx:212` 渲染成 `div`）；`IntegrationView` 的需求号匹配用完整 identifier 严格等值，正则只捕到数字时跳转入口静默退化为不可点 Chip；`⌘[` 会同时"后退"和"翻页"。

严重度口径：**P0** = 远端写入在 UI 层零门控 / 只读承诺被打破；**P1** = 明确违反规范且用户可感知（含无障碍硬阻塞）；**P2** = 一致性、打磨、可维护性。
