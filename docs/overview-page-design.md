# 总览页面详细设计

> 状态：设计提案，尚未实施
> 日期：2026-10-28
> 范围：nervd 桌面端总览页面；本文不改变现有 IPC 契约，也不代表已完成接口联调。

## 1. 目标与设计原则

总览是当前项目空间的交付首页，帮助用户快速了解当前迭代进展、发现重点仓库的构建异常，并进入需求或构建上下文。页面以真实数据为基础，清楚说明范围、完整性和更新时间。

设计原则：

1. 先展示需要处理的异常，再提供完整工作台入口。
2. 项目空间、迭代、类别、重点仓库等统计范围必须可见。
3. 未加载、部分加载、空结果和失败分别呈现；未知不算作零或正常。
4. 工作项以迭代为范围；仓库 CI 以设置中的重点仓库为范围，不暗示 CI 记录属于该迭代或某个需求。
5. 沿用 `DESIGN.md` 的 Linear 风格、语义色和键盘可访问性；桌面宽度优先，较窄窗口按区块纵向排列。

非目标：在总览中复刻完整迭代列表、工作项编辑器、构建日志或设置页面；推断未定义的阻塞、风险、完成率或需求级构建成功率。

## 2. 现状与接口约束

| 数据 | 当前来源 | 已知约束 |
|---|---|---|
| 项目空间与重点仓库 | `SettingsView.defaultSpaceIdentifier`、`watchedRepos`、`repoCiBindings` | 重点仓库是用户配置的子集；每仓库一个当前 CI 绑定，多个仓库可绑定同一 Job。 |
| 迭代 | `list_iterations` → `IterationSummary` | 当前仅请求第 1 页、每页 100 条；空列表在后端作为错误返回；前端接口失败时有示例迭代回退，不能作为真实统计范围。 |
| 工作项 | `list_workitems(category, spaceIdentifier, nextToken)` | 需求、缺陷、任务分别查询；每页 50 条，后端按 `gmtModified` 倒序；接口当前不支持服务端按迭代筛选，需按 `sprintId` 客户端过滤。 |
| 工作项状态 | 列表行 `status`、`statusStageName` | 项目可有自定义状态；尚未验证状态阶段能统一推导完成、阻塞语义。 |
| 仓库 CI | `get_repo_ci_snapshot(repoId, maxResults)` | 通过当前绑定查询 Flow 或 Jenkins；当前默认取近期 5 次，快照状态取首条运行；历史不按工作项或迭代筛选。 |
| 云效流水线 | `list_pipelines`、`list_pipeline_runs` | 当前列表请求第一页最多 20 条，仅前 10 条拉运行记录；组织级范围可能与重点仓库绑定的 Flow 重复。 |
| 更新日期 | 工作项 `updatedAt`；CI 运行时间 | 工作项时间在 Rust 层转换成无时区字符串；需验证显示时区和排序。CI 时间字段缺失时不能推断。 |

现有总览使用共享的当前类别 `items` 计算工作项数量、状态分布和最近更新，数据完整程度会受此前列表加载影响；流水线加载失败也可能表现为空。本文定义的是目标行为，不把现状当作已具备的能力。

## 3. 信息架构与布局

```text
总览                 项目空间 / 迭代选择                 刷新
数据状态：工作项更新于 …  ·  CI 部分查询失败

需要关注
  失败构建 / CI 查询失败 / 待配置提示

当前迭代
  名称、状态、起止日期、剩余天数              进入迭代
  需求 / 缺陷 / 任务：数量与原始状态分布、数据完整性

交付状态
  重点仓库、绑定的 CI、最新状态及构建信息      管理配置

最近更新                                 需求 / 缺陷 / 任务
  状态、编号、标题、负责人、更新时间          打开详情
```

纵向顺序固定为：页头、需要关注、当前迭代、交付状态、最近更新。大屏可在不改变阅读顺序的前提下让当前迭代与需要关注并列；窄窗口单列。列表优先采用裸行与细分隔线，少量分组容器遵守项目圆角和颜色规范。工作项编号、构建号和统计数字使用项目等宽字体规范。

### 3.1 页头与范围

- 标题“总览”；展示当前组织/项目空间的可识别名称。名称未取得时展示明确的 ID 或“未配置项目空间”，不虚构名称。
- 展示当前选中真实迭代及切换入口。总览内切换只改变总览范围，不强制跳转；进入迭代页时携带同一选择。
- 使用迭代 ID 作为身份，名称用于显示；同名迭代不得合并。现有 UI 以名称作为选择键，落实此行为需要处理现有导航状态，属于后续实现工作。
- 刷新入口触发各区域刷新，显示进行中和汇总结果；单区域失败不阻止其他区域展示。
- 按数据域展示上次成功时间或部分失败提示，不能用某一个仓库成功的时间代表所有仓库成功。

### 3.2 需要关注

第一版只显示有确定证据的事项：

1. **失败构建**：重点仓库的已绑定 CI 查询成功，最新运行被规范化为失败。显示仓库、提供方 / Job、运行号（有值时）、运行时间（有值时）及查看日志入口。
2. **CI 查询失败**：展示仓库、失败原因的可读摘要和重试入口。若存在上次成功快照，展示为“上次成功查询：状态 / 时间”，不作为当前状态计数。
3. **尚未绑定 CI**：作为独立配置提示显示数量和设置入口，不计为构建失败。

排序：失败构建 → 查询失败 → 未绑定提示；同组按可用运行时间或仓库名稳定排序。展示条目过多时默认显示前 5 条并提供展开；计数覆盖本区域全部已评估目标。

只有所有已绑定目标本次查询成功且没有失败构建时，才能显示“重点仓库暂无失败构建”；若有查询失败或尚未查询，显示“部分状态未知”。没有重点仓库时引导配置，不能显示“全部正常”。第一版不根据状态名或更新时间推断工作项阻塞、逾期或长期停滞。

### 3.3 当前迭代

- 展示迭代名称、云效返回的状态、起止日期和剩余天数；缺失日期明确显示未知。
- 分别展示需求、缺陷、任务的统计与原始状态分布。默认突出需求，其他类别同等可访问。
- 每个类别显示独立的数据状态：加载中、已加载 N 条、加载完成、失败；完成之前不称为总数。
- 状态按原始名称分组，空值为“状态未知”，所有组均可查看；颜色与 `StatusIcon` 一致，但图标颜色不是统计语义的依据。
- 提供“进入迭代”及类别入口；带入同一真实迭代与类别。现有筛选条件是否延续需明确显示，默认不让隐藏的个人筛选改变总览统计。
- 不展示完成率和阻塞数量，直到状态阶段及工作流映射经过真实项目验证并形成明确规则。

### 3.4 交付状态

以 `watchedRepos` 的唯一仓库 ID 为列表范围，按用户配置顺序展示；如果配置顺序不稳定则按仓库名称稳定排序。每行展示：

- 仓库名称或路径；名称尚未加载时显示仓库 ID。
- CI 提供方与绑定名称；未绑定显示“未绑定 CI”。
- 当前查询状态；成功取得快照时展示最新运行状态、运行号、开始时间和耗时，缺值标“未知”。
- 查看日志、单项刷新；未绑定时提供设置入口。保留触发构建入口时必须遵守现有前后端写门控及确认规则。

摘要按仓库数展示：重点仓库、已绑定、失败、查询失败、未绑定等，标签必须注明“仓库”。同一 Job 绑定两个仓库时按两个仓库计数，不解释为两条独立流水线或两次构建。取消与未知独立显示，不并入失败；等待和运行可合称“进行中”，但保留原始状态可查看。

组织级 Flow 流水线与仓库绑定存在重叠，第一版不与仓库 CI 汇总。若保留流水线墙，应单独标明“组织级 Flow，当前接口返回的前 N 条”，注明列表不保证完整；加载失败和无记录分开。是否保留该次级区块待产品确认，默认总览优先展示重点仓库。

### 3.5 最近更新

- 范围：当前项目空间、选中真实迭代、所选类别；提供需求 / 缺陷 / 任务切换，每类最多展示 8 条。
- 工作项按更新时间倒序，时间相同按 `workitemId` 稳定排序；缺失时间排在最后并显示“时间未知”。
- 行包含状态、编号、标题、负责人和更新时间；点击打开现有详情抽屉，抽屉内可进入完整工作台。
- 后端按修改时间倒序，但迭代过滤在客户端：从头继续请求页，直到获得至少 8 条匹配记录或确认分页结束。需对跨页变动、重复 ID、同时间边界与接口排序进行验证；未能确认完整性时明确显示“已加载范围”，不可声称全范围最近更新。
- 列表可独立于完整统计逐步展示，但数据来源必须与范围一致；不能混入之前访问其他迭代或类别的共享缓存。

## 4. 统计口径

| 指标 | 定义与展示条件 |
|---|---|
| 工作项数量 | 对某一类别从第一页开始逐页加载，以非空 `workitemId` 去重后，筛选 `sprintId` 等于选中真实迭代 ID。只有该类别分页确认结束且无未解决错误时称“总数”；否则显示“已加载 N 条”。无有效 ID 的记录列为异常，不计入可信总数。 |
| 状态分布 | 使用上述同一集合按 `status` 原值分组，空值归“状态未知”。在数据未完整时明确标为已加载范围。各组之和等于可计数工作项数量。 |
| 工作项总计 | 第一版不把需求、缺陷、任务相加，以避免类别重叠或业务理解不一致；各类别独立展示。 |
| 已完成 / 完成率 | 第一版不展示。需先确认 `statusStageName`、自定义工作流及关闭、取消等状态的映射，定义分子、分母与未知状态处理。 |
| 负责人数量 | 第一版不作为核心指标；如后续使用，以非空 `assignedToId` 去重，缺失 ID 单独处理，不能按姓名推断人数，也不能把负责人称作“认领人”。 |
| 重点仓库 | `watchedRepos` 中去重后的仓库 ID 数；不是组织下所有仓库。 |
| 已绑定 | 重点仓库中存在有效 `repoCiBindings` 的仓库数。绑定失效或查询失败不等于未绑定，应分别显示。 |
| 仓库 CI 最新状态 | 成功查询的仓库快照所返回的最新运行状态；无记录、未知枚举、查询失败及未绑定独立计数。对共享 Job 按仓库维度计数。 |
| 失败构建 | 在当前成功查询的重点仓库中，其最新运行映射为失败的仓库数；不是一段时间内的失败构建次数。取消不默认归为失败。 |
| 构建通过率 | 第一版不展示；最近 5 次记录不是固定时间窗口的完整样本，最新状态成功占比也不能称作构建通过率。 |
| 最近更新 | 当前迭代和所选类别中按有效更新时间倒序取最多 8 条；在排序、分页和时间语义未验证时标注“已加载范围”。 |
| 剩余天数 | 结束日期减用户本地今天的日历天数；0 显示“今天结束”，负数显示“已过结束日期 N 天”，缺失显示“结束日期未知”。该文案不替代云效返回的迭代状态。 |

分页中的远端数据可能变化，去重不能消除所有遗漏。结果描述为一次加载期间的统计快照；如需严格一致的全量统计，需要服务端支持稳定快照或聚合接口。当前分页以返回满 50 条推断下一页，恰好满页时可能需要额外请求空页才能确认结束。

CI 状态归一化应建立经联调验证的 Flow / Jenkins 映射表，保留原始值；未识别值归“未知”，不能自动归成功或失败。工作项日期当前转换输出无时区字符串，不能直接声称是用户本地时间；实施前应确认时间含义并统一显示规则。

## 5. 数据获取与刷新策略

1. 初始化先读取设置、真实迭代和重点仓库配置；未配置项目空间时给出设置入口，不发起无效工作项查询。
2. 对选中迭代，需求、缺陷、任务分别维护请求、分页游标、完成状态和错误；请求参数包含项目空间、类别和迭代筛选上下文。已有接口仍按空间与类别取页，客户端按迭代过滤。
3. 分页从第一页开始，以稳定 ID 去重，逐步展示已加载数据。后台继续加载时限制并发和请求量；若设置页数或时间上限，达到上限即标记部分结果，不冒充完整。具体上限需根据真实项目规模和服务限制确定。
4. 项目空间、迭代、类别或配置发生变化时，旧请求结果不得覆盖新范围；显示的缓存必须携带来源范围与最后成功时间。
5. CI 以仓库为独立查询单元，记录每个仓库的成功时间、错误和旧快照；单项重试不阻塞其他仓库。可以复用现有轮询，但刷新摘要应依据每项结果计算。
6. 全局刷新并发发起各数据域的刷新，分别报告成功、部分成功、失败；无缓存的失败区域保留错误与重试。避免因某一请求成功而重置其他区域错误。
7. 日期与时间显示使用用户本地时区并说明；在工作项时间原始值和时区语义得到确认前，不能保证该目标已满足。

## 6. 空、错误与加载状态

| 场景 | 展示和行为 |
|---|---|
| 首次加载 | 与真实布局一致的骨架；数值显示占位，不显示 0。 |
| 刷新中有旧数据 | 保留旧数据，显示“刷新中”和上次成功时间。 |
| 分页未结束 | 展示“已加载 N 条 / 正在加载”或“数据未完整”；状态分布同时标注范围。 |
| 分页失败 | 展示已加载数量、失败和重试；不显示完整总数。 |
| 请求失败有缓存 | 展示旧结果、缓存时间及本次失败；旧结果不得作为当前成功状态。 |
| 成功但结果为空 | 分别显示“该迭代暂无此类工作项”或“该 Job 暂无构建记录”。 |
| 迭代接口无结果或失败 | 当前后端将空迭代作为错误返回，现有契约无法可靠区分空列表与部分失败；按可识别错误显示相应提示，否则显示“迭代不可用”及重试，不呈现示例迭代。 |
| 未配置空间 / 重点仓库 / CI | 给出相应设置入口；未配置不计作失败或零风险。 |
| 部分 CI 未查询或失败 | 显示“部分状态未知”，不显示“全部正常”。 |

## 7. 交互与可访问性

- 所有可操作行提供可辨识名称、键盘焦点和可见焦点环；状态不只依赖颜色。图标应有文字或可访问标签。
- 工作项点击或键盘激活打开现有 Peek Drawer；关闭后焦点返回触发项。抽屉内全屏打开沿用既有导航。
- 保持现有全局快捷键和分层 `Esc` 行为；总览中的筛选、菜单及抽屉不能抢占输入框或最上层浮层的按键。
- 切换迭代或类别时告知加载状态；刷新、失败和后台结果变化采用适当的无障碍状态提示，避免每次轮询重复播报。
- 总览只读浏览默认不需要写权限；触发构建等写操作沿用 `WriteOpButton` / `WriteOpGatedTrigger`、确认交互和 Rust 二次门控，不新增绕过路径。

## 8. 验收场景

1. 同一空间中存在多个迭代，工作项跨多页：三个类别只统计选中迭代，类别分别标记完成，访问迭代列表前后统计口径一致。
2. 后续页失败、恰好 50 条或达到加载上限：页面显示部分结果或失败，不显示完整总数；重试后可恢复。
3. 同名迭代、缺失 `sprintId` 或工作项 ID：不按名称误归属；异常数据不计入可信总数。
4. 当前迭代匹配项散落多页：最近更新继续回填，并正确提示结果是否完整。
5. 两个仓库绑定同一 Job：仓库摘要明确按两个仓库计算，不呈现为两次构建；组织级 Flow 不与其合计。
6. 一项 CI 失败、一项查询失败、一项未绑定：三者分别呈现；旧快照不被误标为当前成功；无“全部正常”。
7. 所有已绑定 CI 查询成功且无失败：显示“重点仓库暂无失败构建”；未配置仓库时显示配置引导。
8. 迭代接口失败、空结果、时间缺失和未知状态：不展示示例数据或推断的完成率，提供可理解的状态。
9. 范围切换与刷新交错：旧请求不能覆盖新范围；各区更新时间及错误独立。
10. 键盘可达、抽屉关闭恢复焦点，深浅主题、窄窗口与长文本均可使用；写操作遵守既有门控。

## 9. 待确认与验证

- 用户是否需要组织级 Flow 次级区块；其完整分页与排序能力需验证。
- 项目中各工作项类别是否可能交叉，以及 `statusStageName` 与完成、取消、阻塞语义的映射。
- 迭代超过 100 条时接口分页、空结果和失败的区分；同名迭代的导航兼容策略。
- 工作项接口排序、分页变化、时间戳时区，以及可接受的后台回填开销和上限。
- Flow / Jenkins 状态映射、首条运行是否稳定代表最新运行，以及日志入口对不同运行的可用性。
- 如未来需要精确完成率、跨时间窗口构建通过率、阻塞或逾期提醒，应先确认业务规则与服务端数据能力，再扩展设计。
